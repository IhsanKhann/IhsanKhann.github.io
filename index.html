01 Selected decisions

Each names what I rejected and what it cost. A decision with no stated cost was not a decision.

  1. Prevented a duplicate accounting system before it shipped

    A second double-entry ledger was scheduled for the marketplace. Its refund rule contradicted the one already in production, so I removed the design rather than reconcile two ledgers, and added a test that fails the build if the routes return.

    Rejected
    Reconciling two ledgers with contradicting buyer policies
    Accepted cost
    One service can now only estimate figures, never own them

  2. Stopped a database change that would have slowed every write

    Asked to add two voting members for high availability, I measured the real latency between the two data centres at 25 ms — not the 35 ms the plan assumed — and found the consequence no configuration diff would show: majority acknowledgement is one member at one, two at three, so an unchanged write concern silently begins requiring a cross-datacentre round trip on every write. A partition would also have taken a healthy node read-only.

    Rejected
    The high-availability plan as written
    Accepted cost
    The platform stays single-homed until the topology changes

  3. Made it impossible for an agent to change data on its own

    Every change an agent produces is a proposal a person reviews and approves, applied through ten domain handlers behind a commit guard. A test fails the build if any agent path writes directly. External agents get the same tools and the same server checks as the in-app assistant — never more.

    Rejected
    A separate, more capable write API for agents
    Accepted cost
    A slower loop, and an approval queue somebody has to work

  4. Seeded no statutory payroll rather than plausible defaults

    A provisioning path was issuing one country's tax deductions to companies that had selected a different jurisdiction, and a second activation path kept its own copy of the defaults. I merged both into one module and chose to seed nothing: a wrong deduction takes real money from a salary silently, while a blank field gets noticed and corrected before the first payroll run.

    Rejected
    A generic default deduction set for unknown jurisdictions
    Accepted cost
    Payroll cannot run until an operator configures it

A platform of five separately sellable products

A multi-vendor marketplace, a multi-tenant ERP, a config-driven console engine, a messaging service and shipment tracking. No product is a module of another; they compose so one organisation runs its commerce and its operations on the same party identity, event stream and financial facts.

The interesting problem was never a feature. It was where the boundary goes — what is a product, what is a shared primitive, and what each service may assume about the others. So the boundary is a test, not a convention: the dependency direction and the tenant seam are asserted by suites that walk the real router, including roughly 48 that prove one customer's data cannot be read by another.

  • 36 engines over 16 shared kernel namespaces
  • 244 tables · 66 declared integration events
  • Load tested at 300 concurrent users with zero HTTP errors

Getting a customer's data out of the system they are leaving

“Can you get our data in” decides more enterprise deals than any feature, so the onboarding pipeline became its own product: parse, map, validate, guardrail, commit — for CSV, JSON, XLSX and raw SQL dumps.

Every external dependency is an injected adapter, so the same engine runs on MongoDB or SQLite, a cloud queue or memory, local disk or object storage, single- or multi-tenant, with no change to the pipeline. Files are read as a stream, so memory use follows row width rather than file size — a 2 GB upload costs no more memory than a small one. Commits deduplicate on a natural key and resume where they stopped.

  • Extracted from the platform, then adopted back by it as a dependency
  • Published standalone with its own documentation site

One tool surface, operated by a person or an agent

An MCP server built from the protocol up — envelope, dispatcher, tool generator, tool surface, commit guard. Pages declare what they show and what they let you do, once, and both the in-app assistant and an external agent read that same declaration. Agents never click screen elements; they call tools that were declared in advance.

Releases are gated on measurement rather than demonstrations: one harness scores conversations, another runs whole tasks repeatedly against a database snapshot, and every scoring set carries prompt-injection, invented-number and cross-customer cases. I score on questions actually answered, not questions kept away from support — the second rewards an assistant that stonewalls.

  • A seller's API key stays in their browser and never reaches the server
  • 10.0 and 9.5 across 44 scored cases on two models
  • Spend attributes to the request that caused it, not to the service

Choosing what the product would not do, and shipping because of it

A compliance and risk product for Pakistan's importers. Shipment tracking was the obvious feature and I ruled it out: tracking only works if you already handle the booking, which makes it an adoption problem no small team wins. Compliance is a reasoning problem over rules and documents — it needs no cooperation from anyone else and no hardware. We built that instead, and wrote the excluded scope down: 8 problems solved, 4 partly, 9 deliberately out.

The retrieval pipeline is hand-built — PDF and OCR parsing for scanned customs documents, chunking, embeddings and a vector store over a nine-document corpus — behind four agents and a router. Country rules stay out of the engine, so a second country is a configuration file rather than a code change.

  • Five risk types, each monitored differently; one deliberately raises no alerts
  • Kept building it after the deadline

An agent near production that cannot author a command

A daemon that collects telemetry from four sources, judges anomalies against both fixed thresholds and learned baselines, and advances an incident lifecycle rather than inventing one. Triage goes to a fast model for latency; code patches go to a stronger one. Two providers and two failure modes, accepted rather than paying frontier latency on every alert.

The safety boundary is the design: recovery runs only scripts from a pre-vetted allowlist, so the agent can propose a fix and cannot compose an arbitrary command. An agent this close to production should be unable to do the wrong thing, not merely discouraged from it.

  • Reports over a live dashboard and accepts commands back
  • Runs on its own instance, separate from what it watches

Also

  • Constraint-aware reinforcement learning — spacecraft attitude control compared across PID, standard RL and a reward-shaped variant, judged on actuator smoothness and control energy rather than tracking error alone. Reproducible from one command.
  • MockServerOB — a fault-injecting mock of a partner API, with configurable latency and error rates. Its own control endpoints are exempt from the faults, so a chaos run stays steerable.
  • langgraph-marketing-agent — a multi-agent content pipeline as a state machine, every tool call over MCP, each carrying a run identifier so cost is attributable per run.

03 How I work

A rule that isn't a test is a preference

The dependency direction, the tenant boundary and the vocabulary each service may use are asserted by suites that read the running application. Adding a legitimate exception means editing a test on purpose.

A measurement is code, and it can be wrong

An internal audit I ran produced six confident figures that were wrong because the predicate asked a slightly different question. Now every reported number carries a confidence class and a date, and an aggregate is not believed until three named instances have been read by hand.

I would rather kill a plan than ship it

Twice this year the useful output was a measurement that stopped work: a replica-set expansion that would have re-priced every write, and a second ledger that would have contradicted the first. Both were reported instead of built.
